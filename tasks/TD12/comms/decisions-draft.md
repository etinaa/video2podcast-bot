## D17: Ollama through Spring AI (TD12, 2026-11-24)

**Decision:** `LlmClient` is implemented by `OllamaLlmClient` on Spring AI's `OllamaChatModel`; the hand-written `HttpClient` `OllamaClient` is removed. New dependency: `org.springframework.ai:spring-ai-starter-model-ollama`, version **2.1.0** from `spring-ai-bom` (property `spring-ai.version` in `pom.xml`). It is the current GA of the Spring AI line for Spring Boot 4. Its POM declares Spring Framework 7.1, but Boot 4.1.2's BOM resolves Framework 7.0.10 and Jackson 3.1.7; this combination compiles and passes all tests. Every request carries `model`, `num_ctx`, `num_predict`, `temperature` 0.2, `keep_alive` 10m and `think:false` as per-request `OllamaChatOptions`; `prompt_eval_count` is read from `Usage.getPromptTokens()` and a missing or zero value is still a failure. `SummaryConfig` builds `OllamaApi` and `OllamaChatModel` itself from `app.ollama.*` (`OLLAMA_BASE_URL`, `OLLAMA_MODEL`, `OLLAMA_NUM_CTX`, `OLLAMA_TIMEOUT` as before): a JSON converter that does not coerce scalars (a number where text is expected is an invalid answer, as before), a JDK `HttpClient` forced to HTTP/1.1 with a 5 s connect timeout and no redirects, the answer timeout as the read timeout of the request factory, and a `RetryTemplate` with no retries (Spring AI's default retries 10 times). Failures keep the three kinds: a refused or unresolved connection or a connect timeout is `CONNECTION` (`SUMMARY_UNREACHABLE`), a read timeout is `TIMEOUT`, everything else is `OTHER`; the kind comes from the cause chain of Spring's `ResourceAccessException`. The health check (`GET /api/version`) moved unchanged into `OllamaProbe`; Whisper is untouched.

**Consequences:** the starter's own auto-configurations (Ollama API, chat, embedding, decision, chat client, chat memory, tool calling, retry, observations) are excluded in `application.yml`, so Spring AI adds no bean except `ollamaApi` and `ollamaChatModel`, and the model is never pulled (`SpringAiWiringTest`). Spring AI needs `Content-Type: application/json` on the answer (real Ollama sends it); a stub without it fails. The request body has an extra `"tools":[]`. Our own JSON parsing is replaced by Spring AI's; the invalid-answer cases of T10 still fail (`OllamaLlmClientTest`).
