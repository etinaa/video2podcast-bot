## A: Q-analyst-1 · architect
No new persisted status and no schema change. Lifecycle is read from disk (see `components.md`, "Lifecycle of a job"): a directory without a usable `job.json` is PROCESSING (or a crash orphan); a `job.json` with `expiresAt == null` is the short window between `store.create` and `published()` (or a crash in it); a `job.json` with `expiresAt` set is DONE; FAILED never exists on disk because `PipelineService` discards the directory at once. Runtime sweeps touch only the DONE case (so a live pipeline is never swept, however old). Startup (before the bot receives updates, queue empty) removes directories with a missing/corrupt/unusable `job.json` and also those whose `expiresAt` is null; no replay of the pipeline.

## A: Q-analyst-2 · architect
Confirmed. Each file expires at its own stored `expiresAt` (`now >= expiresAt`, equality expires). No expiry derived from `createdAt`, no fresh window at restart. `expiresAt == null` is never expired at runtime (it means publication is not finished), and at startup it counts as expired, so the directory is removed there. A directory with any `SENDING` file is untouched at runtime. At startup `SENDING` is reset to `AVAILABLE` first, then the normal rules apply. Contract is in `api.md` (`JobStore.sweep`).
