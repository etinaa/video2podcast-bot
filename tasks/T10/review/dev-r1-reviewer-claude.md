## Findings
- [Important] src/main/java/com/video2podcast/summary/OllamaClient.java:191 - `app.ollama.model` is never validated. `api.md` says the model "must not be blank", and R1/R2 say invalid settings must fail before a request is sent. With `OLLAMA_MODEL=` (blank), every request goes out with `"model": ""` and the failure only shows up at run time as a 400 turned into FAILED. The same applies to `timeout`: a null, zero or negative value makes `HttpRequest.Builder.timeout` throw `IllegalArgumentException` (or NPE) inside `send()`, outside the `try`'s caught types, so the exception escapes `SummaryService.summarize` as a raw runtime exception instead of a `JobFailure`. Validate `model` (not blank) and `timeout` (positive) in the constructor of `OllamaClient` or `SummaryService`, as is already done for `numCtx`, so that the application fails at start. Add unit tests for blank model and non-positive timeout.
- [Suggestion] src/main/java/com/video2podcast/summary/SummaryService.java:461 - `(int) (textBudget * 3)` overflows for `numCtx` above about 715 million (for example `Integer.MAX_VALUE`). `maxChunkChars` becomes negative and the first request fails in `TextChunker` with an `IndexOutOfBoundsException`. `aHugeContextDoesNotOverflow` only tests `MAX_VALUE / 4`. Cheap fix: reject a `textBudget` over `Integer.MAX_VALUE / 3` in the constructor, or use `Math.toIntExact`/`Math.min`.
- [Suggestion] src/test/java/com/video2podcast/summary/SummaryServiceTest.java:1585 - the round tests assert group sizes and order well, but no test pins that a group's answer replaces the partials for the next round when a second round happens in a way that shows the *content* order (only counts are checked in `seventeenPartialsNeedTwoRoundsOfReduction`). Low risk, since `partials = next` is trivial. Optional.
